## 1. 概要

### 1.1 目的

自分のレシピを1か所にまとめ、料理名・材料・カテゴリ・タグなどから、作りたいものをすぐに探せるようにする。作った記録を残し、レシピの改良や献立決めに役立てる。

### 1.2 背景（課題の条件）

RaiseTech 初級編の最終課題として作る。課題の条件は次のとおり。

- 要件定義から設計・開発・AWS へのデプロイまでを一通り行い、**GitHub のリポジトリの URL を提出する**（公開したアプリの URL は提出しない）
- 初級編で使った技術（React・TypeScript・Vite・Tailwind CSS、Java・Spring Boot・Gradle・PostgreSQL）と**違う技術スタックを使う**

### 1.3 利用者

利用者は**持ち主（自分）1人だけ**。アカウントも1つだけ。

- ログインしていない人は、どの画面を開いてもログイン画面になる。中身は一切見られない
- ログイン状態は端末ごとに長期間保たれるので、ふだんはログインを意識しない
- 新規登録の画面は作らない。持ち主のアカウントはコマンドで作る

## 2. 機能要件

ID の頭文字：F = 機能（Function）。

### 2.1 レシピ

| ID | 機能 | 内容 |
|---|---|---|
| F-01 | レシピ一覧 | 写真（小さな画像）・料理名・カテゴリ・タグ・調理時間・お気に入りを並べて表示する。20件ずつ表示し、「次へ」で続きを見る |
| F-02 | レシピ詳細 | 3章の項目をすべて表示する。スマホでも材料と手順が読みやすいこと |
| F-03 | レシピ登録 | 3章の項目を入力して登録する |
| F-04 | レシピ編集 | 登録した内容を変更する。材料・手順の行の追加・削除・並び替えができる |
| F-05 | レシピ削除 | 確認のうえ削除する。材料・手順・作った記録・写真も一緒に消す |
| F-06 | レシピ複製 | 既存のレシピをコピーして、新しいレシピを作る（4.3 参照） |
| F-07 | お気に入り | ★ のオン・オフを切り替える |

### 2.2 探す（一覧画面）

次の条件は**組み合わせて**使える（例：カテゴリ「主菜」＋タグ「時短」＋キーワード「豚肉」）。

| ID | 機能 | 内容 |
|---|---|---|
| F-11 | キーワード検索 | 料理名と材料名から探す（部分一致） |
| F-12 | カテゴリで絞り込み | 1つ選ぶ |
| F-13 | タグで絞り込み | 1つ選ぶ |
| F-14 | お気に入りだけ表示 | オン・オフ |
| F-15 | 調理時間で絞り込み | 「15分以内」「30分以内」「60分以内」から選ぶ |
| F-16 | 並び替え | 新しい順（初期値）・料理名順・調理時間の短い順・最後に作った日が古い順 |
| F-17 | ページ分け | 20件ずつ。検索・絞り込み・並び替えの条件は、ページを移っても保つ |

### 2.3 写真

| ID | 機能 | 内容 |
|---|---|---|
| F-21 | 完成写真の登録 | 1レシピに1枚。登録・編集画面で選ぶ。なくてもよい |
| F-22 | 写真の差し替え・削除 | 別の写真に変える、写真だけ消す。古い写真は保存先からも消す |
| F-23 | 写真がないときの表示 | 「No Image」の画像を出す |

写真の決まりは 4.2 を参照。

### 2.4 カテゴリ・タグ

| ID | 機能 | 内容 |
|---|---|---|
| F-31 | カテゴリの選択 | 固定の12個（4.1）から1つ選ぶ。必須 |
| F-32 | タグの付け外し | レシピの登録・編集画面で、タグ名を入力して付ける。まだないタグ名なら、新しいタグが自動でできる。既存のタグは候補として出す |
| F-33 | 使われていないタグの片付け | どのレシピにも付いていないタグは自動で消す（絞り込みの候補に残らないように） |

### 2.5 作った記録

| ID | 機能 | 内容 |
|---|---|---|
| F-41 | 記録の追加 | レシピ詳細の「作った」から、日付（初期値は今日、変更できる）とひとことメモ（任意）を残す |
| F-42 | 記録の表示 | レシピ詳細に「作った回数」「最後に作った日」と、記録の一覧（新しい順）を出す |
| F-43 | 記録の削除 | 押し間違いなどの記録を消す |

### 2.6 アカウント

| ID | 機能 | 内容 |
|---|---|---|
| F-51 | ログイン | メールアドレスとパスワードでログインする。ログイン状態は長期間保つ |
| F-52 | ログアウト | 設定画面に置く（共用の端末でログインしたとき用） |
| F-53 | パスワード変更 | 設定画面で、今のパスワードと新しいパスワードを入れて変える |
| F-54 | 持ち主アカウントの作成 | 画面ではなくコマンドで作る。アカウントは1つだけ |

### 2.7 ログインしていない人への扱い

| ID | 内容 |
|---|---|
| F-61 | ログインしていない人がどの画面を開いても、ログイン画面に移す。ログインしたら、もともと開こうとした画面に戻す |
| F-62 | 画面だけでなくサーバー側でも、ログインしていない人からの要求（見る・変える）をすべて断る |

## 3. レシピの項目

| 項目 | 必須 | 決まり（目安。基本設計で確定する） |
|---|---|---|
| 料理名 | ○ | 100文字まで |
| カテゴリ | ○ | 固定の12個から1つ（4.1） |
| タグ | | 1レシピに10個まで。1つ20文字まで |
| 何人分 | ○ | 1〜99（人分） |
| 調理時間 | | 1〜999（分） |
| 材料 | ○（1行以上） | 「名前」と「分量」の組。50行まで。名前は50文字、分量は30文字まで（「200g」「少々」「大さじ2」など自由に書ける） |
| 作り方（手順） | ○（1行以上） | 番号順に並ぶ文章。50行まで。1行500文字まで |
| メモ | | 2000文字まで |
| 完成写真 | | 1枚（4.2） |
| お気に入り | | オン・オフ |

このほか、システムが自動で持つもの：登録日時、更新日時。

## 4. 決まりごと

### 4.1 カテゴリ（固定）

| # | カテゴリ | 例 |
|---|---|---|
| 1 | 主菜 | 肉じゃが、唐揚げ、焼き魚、麻婆豆腐 |
| 2 | 副菜 | きんぴら、おひたし、ポテトサラダ |
| 3 | サラダ | グリーンサラダ、春雨サラダ |
| 4 | 汁物・スープ | 味噌汁、ポタージュ、豚汁 |
| 5 | ご飯もの | 炒飯、丼、炊き込みご飯、カレー |
| 6 | 麺類 | パスタ、うどん、焼きそば、ラーメン |
| 7 | パン・粉もの | サンドイッチ、お好み焼き、ピザ |
| 8 | お弁当・おつまみ | 卵焼き、枝豆の炒め物 |
| 9 | デザート・おやつ | プリン、クッキー |
| 10 | 飲み物 | スムージー、チャイ |
| 11 | たれ・ソース・調味料 | 焼肉のたれ、ドレッシング |
| 12 | その他 | どれにも当てはまらないもの |

- 「和食・洋食・中華」「時短」「作り置き」など、カテゴリと重なる分け方はタグで付ける
- カテゴリは画面からは変えない。最初に入れるデータ（シーダー）で用意し、変えるときはそこを直す

### 4.2 写真

| 項目 | 決まり |
|---|---|
| 枚数 | 1レシピに完成写真1枚。手順ごとの写真はなし |
| 種類 | JPEG・PNG・WebP |
| 大きさの上限 | 5MB |
| 縮小 | 保存のときにサーバーで縮小する（横幅1200px を目安） |
| 保存先 | 開発中はパソコンの中のフォルダ、AWS では S3。設定で切り替える |

### 4.3 複製

- 料理名の後ろに「（コピー）」を付けた、新しいレシピを作る
- コピーするもの：カテゴリ・タグ・何人分・調理時間・材料・手順・メモ・写真
- コピーしないもの：お気に入り、作った記録
- 複製のあとは、新しいレシピの編集画面を開く

## 5. 非機能要件

ID の頭文字：N = 非機能（Non-functional）。

### 5.1 使いやすさ・表示

| ID | 内容 |
|---|---|
| N-01 | パソコンとスマホの両方で使える（画面の幅に合わせて並び方を変える）。スマホは横幅 320px 以上で、表示が崩れたり横にはみ出したりしないこと |
| N-02 | 対応ブラウザ：パソコンの Chrome・Edge・Firefox（最新版）、iPhone の Safari、Android の Chrome（最新版） |
| N-03 | 入力の誤りは、どの項目がなぜだめかを日本語で表示する |
| N-04 | 削除の前には確認を出す |

### 5.2 性能

| ID | 内容 |
|---|---|
| N-11 | レシピが1000件あっても、一覧・検索の結果がおおむね2秒以内に出る |
| N-12 | 一覧では縮小した写真を使い、表示を軽くする |

### 5.3 セキュリティ

| ID | 内容 |
|---|---|
| N-21 | 通信は HTTPS で暗号化する |
| N-22 | パスワードはそのまま保存せず、元に戻せない形（ハッシュ）で保存する |
| N-23 | ログインに続けて失敗したら、しばらく受け付けない（パスワードの総当たり攻撃を防ぐ） |
| N-24 | ログインしていない人からの要求はサーバー側で断る（F-62） |
| N-25 | 他のサイトからなりすまして操作させる攻撃（CSRF）を防ぐ |
| N-26 | パスワードや AWS の鍵などの秘密の情報は、Git に入れない |
| N-27 | アップロードされたファイルは、中身が本当に画像かを確かめる |

### 5.4 運用・保守

| ID | 内容 |
|---|---|
| N-31 | データベースは AWS（RDS）の自動バックアップを使う（7日分） |
| N-32 | エラーはログに残し、原因を後から調べられるようにする |
| N-33 | サーバー側・画面側それぞれ自動テストを用意し、GitHub に送ったときに自動で実行する |
| N-34 | AWS の費用は、無料枠・クレジットの範囲に収まるようにする |

## 7. 対象外（今回は作らないもの）

| 機能 | 作らない理由 |
|---|---|
| 新規登録の画面 | 利用者は自分1人。アカウントはコマンドで作る |
| ゲスト（ログインなしでの閲覧） | 提出物はリポジトリの URL で、公開したアプリを他人に見せる必要がない。利用者は自分だけ |
| メールアドレス変更・パスワード再設定の画面 | 自分1人なのでコマンドで足りる。メール送信の仕組みが要る |
| カテゴリの追加・編集の画面 | カテゴリは固定 |
| タグの管理画面 | タグはレシピの編集画面で付け外しし、使われなくなったら自動で消える |
| 手順ごとの写真、作った記録の写真 | 写真の扱いが大がかりになる |
| 人数の変換（分量の自動計算） | 分量を数字と単位に分けて持つ必要があり、入力が面倒になる |
| 料理中モード（画面が暗くならない・文字を大きく） | 今回は不要（ユーザー判断） |
| 印刷用の表示 | 今回は不要（ユーザー判断） |
| 栄養・カロリー計算、献立カレンダー、買い物リスト | 大がかりで、もう1つアプリを作るくらいの量になる |
| 参考URL | 今回は不要（ユーザー判断） |
